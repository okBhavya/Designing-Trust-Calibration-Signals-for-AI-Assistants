## 1. System Inventory & Classification Scheme

Every subsystem and component in the CalibrAI repository is audited against actual source code, tests, and database artifacts. Components are categorized using one of nine rigorous statuses:

- **COMPLETE AND VERIFIED:** Code fully implemented, integrated, and verified by passing automated unit/integration tests and typecheck.
- **IMPLEMENTED BUT NOT FULLY VERIFIED:** Code exists and executes, but lacks complete end-to-end live testing, full migration verification, or external environment testing (e.g. PostgreSQL RLS).
- **PARTIALLY IMPLEMENTED:** Partial logic or UI exists, but key functionality (such as sentence-level highlighting or multi-source adjudication) is not wired up or completed.
- **MOCK / FIXTURE ONLY:** Component exists only as a deterministic simulator, local mock, or static file fixture; does not perform real AI inference or web retrieval.
- **SCAFFOLDED:** Structural types, database tables, or protocol interfaces exist, but no functional business logic or provider implementation exists.
- **NOT IMPLEMENTED:** Planned in architecture or blueprint documents, but zero implementation exists in the codebase.
- **BLOCKED BY EXTERNAL DEPENDENCY:** Blocked by third-party licensing, missing API credentials, or external service infrastructure.
- **REQUIRES RESEARCH:** Algorithmic, mathematical, or empirical design decisions must be resolved through academic literature before code can be written.
- **REQUIRES HUMAN APPROVAL:** Gated by Institutional Review Board (IRB) / Ethics Committee, dataset copyright owner, or institutional authority.
