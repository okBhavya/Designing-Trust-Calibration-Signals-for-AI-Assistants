# Deploying CalibrAI

Three parts, deployed separately:

| Part | Where | Config |
|---|---|---|
| API (`apps/api`) + PostgreSQL | Render (any host that runs a Procfile works) | `apps/api/render.yaml`, `apps/api/Procfile` |
| Study harness (`apps/study`) | Vercel (any static host with an SPA fallback works) | `apps/study/vercel.json` |
| Extension (repo root) | Built locally, loaded unpacked or uploaded to the Chrome Web Store | `wxt.config.ts` |

Deploy in this order: API first (you need its URL), then the extension (you need its ID for the
API's CORS list), then the harness (you need the API URL), then add the harness URL to the API.

> **PostgreSQL is not verified yet.** All tests run on SQLite. Before a real study, run the
> migrations and the smoke test (`docs/SMOKE_TEST.md`) against the deployed database, and decide
> how the row-level-security policies from migration `0001` should apply (the app connects as the
> table owner, which bypasses them).

## 1. API on Render

1. In Render: **New > Blueprint**, choose this repository, and set the **Blueprint path** to
   `apps/api/render.yaml`. It creates the `calibrai-api` web service and the `calibrai-db` database.
2. Fill in the values marked `sync: false` when Render asks (table below).
3. Every start runs `alembic upgrade head` before `uvicorn` (Render `startCommand` and the
   `Procfile` use the same command). A failed migration stops the deploy instead of serving an
   out-of-date schema.
4. The app runs one worker on purpose: the rate limiter is in memory, per process.
5. Check `https://<your-api>/health` returns `{"status":"ok","service":"calibrai-api"}`.

At start-up the API refuses to run in production with default secrets, the reliability fixture
provider, the self-consistency provider without `LLM_API_KEY`, a weak or reused study code, or a
non-https study origin.

### API environment variables

| Variable | Required | Value |
|---|---|---|
| `PYTHON_VERSION` | Render only | `3.14.5`, the version the tests run on. |
| `CALIBRAI_ENVIRONMENT` | yes | `production`. Turns on the production guards. |
| `CALIBRAI_DATABASE_URL` | yes | Filled from the Render database. `postgres://` and `postgresql://` URLs are rewritten to the installed psycopg 3 driver. |
| `CALIBRAI_SESSION_SIGNING_SECRET` | yes | Generated by Render. Signs session tokens; at least 32 characters. |
| `CALIBRAI_ENROLLMENT_SECRET` | yes | Generated by Render. The extension's `/v1/session` secret, used by researchers to issue tokens. |
| `CALIBRAI_SIGNAL_PROVIDER` | yes | `selfconsistency` (the real engine). `mock` returns a fixed demo signal. |
| `LLM_API_KEY` | with `selfconsistency` | Anthropic API key. Never commit it. |
| `CALIBRAI_LLM_MODEL` | no | `claude-haiku-5-5` (the default, about $0.001 per signal). |
| `CALIBRAI_LLM_EXTRACTION_MODEL` | no | A different model for claim extraction only. Empty = `CALIBRAI_LLM_MODEL`. |
| `CALIBRAI_CONSENT_VERSION` | yes | `2026-11-04`. Must match `VITE_CONSENT_VERSION` in the harness, or enrollment returns 409. |
| `CALIBRAI_STUDY_ENROLLMENT_CODE` | for the study | The code in the study link (`?code=…`). 12+ characters, different from `CALIBRAI_ENROLLMENT_SECRET`. Empty = study enrollment closed. |
| `CALIBRAI_STUDY_ORIGINS` | for the study | The harness origin(s), comma separated, https only: `https://calibrai-study.vercel.app`. |
| `CALIBRAI_API_ORIGINS` | for the extension | CORS origins, comma separated: `chrome-extension://<extension id>`. Replaces the default list (the chat sites and `http://localhost:5173`). |

Other settings keep safe defaults (`CALIBRAI_SESSION_TTL_SECONDS` 86400,
`CALIBRAI_RATE_LIMIT_REQUESTS` 60 per `CALIBRAI_RATE_LIMIT_WINDOW_SECONDS` 60,
`CALIBRAI_MAX_REQUEST_BYTES` 65536, `CALIBRAI_STORE_RAW_CONVERSATION` false, the self-consistency
thresholds 0.80 / 0.60). See `apps/api/.env.example`.

## 2. Extension

Build with the deployed API as a host permission:

```powershell
$env:WXT_API_ORIGIN = 'https://calibrai-api.onrender.com'
corepack pnpm build        # -> .output\chrome-mv3
```

| Variable | Value |
|---|---|
| `WXT_API_ORIGIN` | The API origin, https, no path. Becomes a host permission and the options page's default API URL. Production builds without it only run in mock mode (the build warns). |
| `WXT_EXTENSION_KEY` | Optional. The manifest `key`, which pins the extension ID (below). |

You can also put these in `.env.production.local`: `.env.local`, `.env.*.local` and `*.pem` files
are git-ignored. Development builds (`corepack pnpm dev`, or
`npx wxt build --mode development` -> `.output\chrome-mv3-dev`) also allow the local API on
`http://127.0.0.1:8000` and `:8010`; production builds never do.

### Get the extension ID and add it to CORS

1. Open `chrome://extensions`, turn on **Developer mode**, click **Load unpacked** and pick
   `.output\chrome-mv3`.
2. Copy the **ID** shown on the CalibrAI card (32 letters a–p).
3. Set `CALIBRAI_API_ORIGINS=chrome-extension://<that id>` on the API and redeploy.

An unpacked extension's ID depends on the folder it was loaded from, so each machine gets a
different ID. To keep one ID everywhere:

1. In `chrome://extensions`, **Pack extension** on `.output\chrome-mv3` once; keep the `.pem`
   file private and out of the repository.
2. Get the public key: `openssl rsa -in chrome-mv3.pem -pubout -outform DER | openssl base64 -A`.
3. Build with `WXT_EXTENSION_KEY=<that base64 string>`. Every build now has the same ID.

A Chrome Web Store upload gets a fixed ID from the store; use that one.

## 3. Study harness on Vercel

1. In Vercel: **Add New > Project**, import this repository, set **Root Directory** to
   `apps/study` and keep **Include files outside the root directory** on: the harness imports the
   overlay from `src/overlay` and the trials from `data/questions.json`.
2. Set the environment variables below, then deploy. `vercel.json` installs the pnpm workspace,
   runs `npm run build`, serves `dist/`, falls back to `index.html` for any path, and sends
   `Referrer-Policy: no-referrer` (the study link carries the enrollment code).
3. Add the deployment URL to `CALIBRAI_STUDY_ORIGINS` on the API.
4. Share `https://<harness>/?code=<CALIBRAI_STUDY_ENROLLMENT_CODE>` with participants.

| Variable | Value |
|---|---|
| `VITE_API_BASE_URL` | The API origin, e.g. `https://calibrai-api.onrender.com`. Without it the build warns and calls `http://127.0.0.1:8000`. |
| `VITE_CONSENT_VERSION` | `2026-11-04`; must equal `CALIBRAI_CONSENT_VERSION`. |
| `VITE_STUDY_ENROLLMENT_CODE` | Optional fallback when the link has no `?code=`. It ends up in the public bundle. |
| `VITE_DEMO` | `1` for a demo deployment that needs no API and saves nothing. |

All `VITE_` values are public: they are compiled into the JavaScript the browser downloads.

## 4. After deploying

Run `docs/SMOKE_TEST.md` end to end, then export a test run with
`python apps/api/scripts/export_study.py --database-url <the Render external URL>` and delete
the test participants before inviting anyone.
