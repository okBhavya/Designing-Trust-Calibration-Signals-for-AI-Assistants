# CalibrAI API contract

The API is a provider-neutral boundary. `platform` is metadata used for
analysis and routing, not factuality logic. Supported values are `chatgpt`,
`claude`, and `gemini`; adding another provider requires extending the shared
enum and adding an extension adapter, not changing signal evaluation.

## Endpoints

- `GET /health` — non-sensitive service status.
- `POST /v1/consent` — create/update a participant consent record.
- `POST /v1/signal` — return a versioned signal after consent verification.
- `POST /v1/events` — record validated interaction events.
- `GET /v1/config?participant_id=...` — return only that participant's
  condition and feature flags.
- `DELETE /v1/participant/{participant_id}` — delete participant data through
  database cascade relationships.

`POST /v1/signal` accepts the same `platform`, `prompt`, `answer`, and
`answerHash` data represented by the extension capture protocol, with
snake_case JSON names at the API boundary. Its response uses camelCase aliases
for direct compatibility with the extension's `modelVersion` and
`processingLatencyMs` fields. The response also includes future-compatible
score, sentence flags, and claim assessments.

The current result is generated by `MockSignalProvider` (`mock-v1`). It is not
a factuality or reliability assessment.
